# База данных JetPing: Архитектура и интеграция

## Как работает база данных

В проекте используется легковесная встроенная СУБД **SQLite3**. База данных представлена одним локальным файлом, путь к которому задается через переменную окружения `JETPING_DATABASE_PATH`. Значение по умолчанию: `data/jetping.db`.

Взаимодействие с базой данных реализовано через стандартную Python-библиотеку `sqlite3`. Telegram-бот работает асинхронно, а SQLite выполняет синхронные операции ввода-вывода, поэтому обращения к БД из обработчиков сообщений и scheduler выполняются через `asyncio.to_thread()`.

## Таблица `searches`

Таблица `searches` хранит историю успешных поисковых запросов и найденных цен. В нее попадают как ручные проверки через `/price`, так и автоматические проверки scheduler.

| Поле | Тип | Описание |
| :--- | :--- | :--- |
| `id` | `INTEGER` | Уникальный идентификатор записи. |
| `user_id` | `INTEGER` | Telegram ID пользователя. |
| `origin` | `TEXT` | IATA-код города вылета. |
| `destination` | `TEXT` | IATA-код города прилета. |
| `departure_date` | `TEXT` | Дата вылета в формате `YYYY-MM-DD`. |
| `return_date` | `TEXT` | Дата возвращения или `NULL`. |
| `service` | `TEXT` | Источник цены, например `Aviasales / Travelpayouts`. |
| `price` | `INTEGER` | Найденная цена. |
| `currency` | `TEXT` | Валюта. |
| `airline` | `TEXT` | Авиакомпания, если источник ее вернул. |
| `link` | `TEXT` | Ссылка на билет, если есть. |
| `timestamp` | `TEXT` | Время сохранения записи. |

## Таблица `tracked_routes`

Таблица `tracked_routes` хранит активные маршруты, которые пользователь хочет отслеживать.

| Поле | Тип | Описание |
| :--- | :--- | :--- |
| `id` | `INTEGER` | Уникальный ID отслеживания. Используется в `/delete <id>`. |
| `user_id` | `INTEGER` | Telegram ID владельца отслеживания. |
| `origin` | `TEXT` | IATA-код города вылета. |
| `destination` | `TEXT` | IATA-код города прилета. |
| `departure_date` | `TEXT` | Дата вылета. |
| `return_date` | `TEXT` | Дата возвращения или `NULL`. |
| `interval_minutes` | `INTEGER` | Интервал проверки в минутах. |
| `last_price` | `INTEGER` | Последняя известная цена. |
| `currency` | `TEXT` | Валюта последней цены. |
| `is_active` | `INTEGER` | Флаг активности: `1` активно, `0` удалено пользователем. |
| `created_at` | `TEXT` | Время создания отслеживания. |
| `last_checked_at` | `TEXT` | Время последней проверки цены. |

## Зачем нужны две таблицы

`searches` - это журнал фактических проверок. Он показывает, что бот уже проверял и какие цены были найдены.

`tracked_routes` - это список активных задач для автоматической проверки. Scheduler читает именно эту таблицу, выбирает маршруты, которым пора провериться, и сравнивает новую цену с `last_price`.

## Как работает scheduler

1. При запуске бота создается background task.
2. Раз в `JETPING_SCHEDULER_TICK_SECONDS` секунд scheduler выбирает записи из `tracked_routes`, которым пора провериться.
3. Запись считается готовой к проверке, если:
   - `is_active = 1`;
   - дата вылета еще не прошла;
   - `last_checked_at` пустой или с момента последней проверки прошло `interval_minutes` минут.
4. Для каждой записи scheduler получает новую цену через текущий `PriceProvider`.
5. Каждый успешный результат сохраняется в `searches`.
6. В `tracked_routes` обновляются `last_price`, `currency` и `last_checked_at`.
7. Если новая цена ниже предыдущей, бот отправляет пользователю Telegram-уведомление.
8. Если проверка не удалась, обновляется `last_checked_at`, чтобы не создавать частый цикл повторов при недоступном API.

## Функции слоя БД

В `db.py` реализованы функции:

- `init_db()` - создает директорию и таблицы;
- `save_search()` - сохраняет успешный поиск;
- `create_tracked_route()` - создает активное отслеживание;
- `list_tracked_routes()` - возвращает активные отслеживания пользователя;
- `list_due_tracked_routes()` - возвращает отслеживания, которым пора провериться;
- `update_tracked_route_price()` - обновляет последнюю цену и время проверки;
- `mark_tracked_route_checked()` - обновляет только время проверки после неудачного запроса;
- `deactivate_tracked_route()` - помечает отслеживание неактивным.

## Команды, связанные с БД

- `/price` - сохраняет результат в `searches`.
- `/track` - сохраняет результат в `searches` и создает запись в `tracked_routes`.
- `/list` - читает активные записи из `tracked_routes`.
- `/delete <id>` - помечает запись в `tracked_routes` как неактивную.

## Текущее ограничение

Scheduler работает внутри процесса Telegram-бота. Если бот остановлен, автоматические проверки не выполняются. Для постоянной работы потребуется деплой на сервер или другой постоянно запущенный хостинг.
